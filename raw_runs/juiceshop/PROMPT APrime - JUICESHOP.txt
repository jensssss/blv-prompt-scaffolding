  Root Cause Pattern
                                                                                                                                                                                    
  All findings share the same underlying design flaw: multi-step workflow state is enforced only client-side (Angular UI). The REST API treats every endpoint as independent and
  stateless — it never checks whether prerequisite workflow steps were completed before allowing the current step. This is a classic "trust the client" business logic failure.     
                                                                                                                                                                                  
  Recommended Remediation:                                                                                                                                                          
  1. Enforce server-side invariants at checkout: basket must be non-empty, total must be > $0, a valid addressId must reference a real address owned by the user, and a valid     
  paymentId must be provided and validated before generating an order confirmation.                                                                                                 
  2. Invalidate/lock the basket after successful checkout to prevent replay.       
  3. Require the current password on the change-password endpoint and validate it server-side before applying the change.                                                           
  4. Enforce review authorship on the PATCH endpoint — only allow editing reviews where author == authenticated_user.email.                                                         
  5. Enforce a "verified purchase" check server-side before accepting review submissions.

  frontend. The frontend checks whether today's date matches the coupon's       
  validOn timestamp, then sends couponData = btoa(couponCode + "-" +

  FLOW-006 — REPLAY — Campaign Coupon Has No Server-Side Replay Prevention      
                                                                                
  SEVERITY: High                                                              
                                                                              
  DESCRIPTION:
  Once a valid (or forged) campaign coupon is applied, the server does not mark
  it as used. The same couponData value can be submitted in unlimited sequential
   checkouts, applying the discount every single time. There is no per-account,
  per-order, or per-campaign usage limit enforced server-side.                  
                                                                  
  BUSINESS IMPACT:                                                            
  Combined with FLOW-005, an attacker can apply a 75% discount to every single
  order indefinitely, paying only 25 cents on the dollar for all purchases.
